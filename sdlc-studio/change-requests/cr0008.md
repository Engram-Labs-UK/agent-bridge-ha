# CR-0008: Re-baseline to bridge v4.137 + capability audit

> **Status:** Proposed
> **Priority:** P1
> **Type:** spec-gap
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** const (drift baseline), client, webhook, CI
> **Depends on:** —
> **GitHub Issue:** —

## Summary

The integration is built and tested against bridge **v4.36.0** while the live bridge is **v4.137.1** - roughly 100 minor releases of new capability. Re-baseline the drift pin, audit the capability delta to decide what is HA-relevant, subscribe to the new `message:sent` webhook event, and validate the client against the bridge's now-published OpenAPI 3.1.1 spec. This is the hygiene gate that should precede any new feature work (CR-0009, CR-0010).

## Problem

`const.TESTED_BRIDGE_VERSION = "4.36.0"`. The live bridge reports 4.137.1 (`agent-bridge/package.json`). The US0029 drift check raises an HA repair issue whenever the live bridge moves past the baseline, so the operator is almost certainly seeing a standing repair notice. Beyond the noise, ~100 releases of new capability (usage/cost, doctor, memory, governed skills, OpenAPI spec, honest pagination, async messages) have landed unexamined, and at least one webhook event the bridge now emits - `message:sent` - is not in `BRIDGE_WEBHOOK_EVENTS`.

---

## Proposed Changes

### Item 1: Bump the drift baseline

**Priority:** P1
**Effort:** S

Set `const.TESTED_BRIDGE_VERSION` to the validated live version (4.137.x). Confirm the existing chat/discovery/health calls still behave against it (live smoke). Note: this is the *bridge* pin and is independent of the HA-core pin in Critical Rule 9.

### Item 2: Capability-delta audit (4.37 → 4.137)

**Priority:** P1
**Effort:** M

Walk the bridge `agent-context` `notable_capabilities` delta. For each, record HA-relevant / out-of-scope with a one-line reason. The HA-relevant set feeds CR-0009 (usage/cost, doctor) and CR-0010 (memory); the out-of-scope set (provider keys, HA failover, crew-trust, config mgmt) is documented so it is not revisited. Output: a short audit note in this CR's close reason or a `reviews/` snapshot.

### Item 3: Subscribe to `message:sent`

**Priority:** P2
**Effort:** S

Add `message:sent` to `BRIDGE_WEBHOOK_EVENTS` and handle (or deliberately ignore) it in `webhook.py`. Confirm the full v4.137 event catalogue against the bridge: `agent:registered`, `agent:unregistered`, `agent:updated`, `agent:health-changed`, `message:sent`, `message:error`, `bridge:upgraded`.

### Item 4: Validate the client against the OpenAPI spec

**Priority:** P2
**Effort:** M

The bridge now publishes OpenAPI 3.1.1 at `GET /v1/openapi.json` (CI-guarded against doc drift). Add a test that checks the `BridgeClient` request/response shapes for the endpoints HA consumes against that spec, so future bridge contract changes surface in CI rather than at runtime.
