# CR-0009: Surface bridge usage/cost and fleet doctor in HA

> **Status:** Implemented
> **Priority:** P2
> **Type:** feature-request
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** client, coordinator, sensor, diagnostics, drift
> **Depends on:** CR-0008
> **GitHub Issue:** —

## Summary

Bring two read-only bridge observability surfaces into Home Assistant: per-agent **usage and cost** (as sensors) and the **one-call fleet doctor** (as diagnostics + a repair issue). Both are pure reads that fit the thin-adapter principle and give the operator spend visibility and health insight without leaving HA.

## Problem

The bridge tracks per-agent token usage and cost in GBP (`GET /v1/agents/{id}/usage`, per-model since 4.108), outbound quota state (`/quota`), and a fleet verdict (`GET /v1/doctor`, since 4.107). None of it reaches HA, so there is no way to build a spend dashboard, budget alert, or health automation from the home side.

---

## Proposed Changes

### Item 1: Per-agent usage & cost sensors

**Priority:** P2
**Effort:** M

Add `BridgeClient` methods for `/v1/agents/{id}/usage` and `/quota`, poll via the existing coordinator, and expose sensors on the existing sensor platform: tokens (today/total), cost (GBP), and quota state. Respect the per-model breakdown where present. Enables budget automations ("notify if monthly spend > £X").

### Item 2: Fleet doctor diagnostics + repair

**Priority:** P3
**Effort:** M

Add a `/v1/doctor` client call. Surface the verdict + findings in HA's diagnostics download, and raise a repair issue when the verdict is unhealthy - complementing the US0029 drift check (same repair-issue machinery, different signal).
