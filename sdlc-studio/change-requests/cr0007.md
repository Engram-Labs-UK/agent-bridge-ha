# CR-0007: Options-flow usability restructure

> **Status:** Implemented
> **Priority:** P2
> **Type:** production-feedback
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** config_flow, strings/translations
> **Depends on:** CR-0006
> **GitHub Issue:** —

## Summary

Make the Agent Bridge options screen legible: split essential settings from advanced tuning, fix the two controls that render as raw `snake_case` keys, add help text to every non-obvious field, and rename "Agent" so it stops colliding with the per-agent conversation entities.

## Problem

A walkthrough of the live options screen (after the CR-0006 cull) found usability defects:

1. **Two fields render their raw config key.** `session_idle_window` and `enable_streaming` have no entry in `strings.json` or `translations/en.json`, so HA shows the snake_case key. They are also the two least obvious settings, so they need both a label and help text.
2. **Help text exists on one field only** (`caller_id`). The cryptic ones - entity-context budget, session continuity window, streaming, response timeout - are guesswork, and the valid ranges (`1000-200000`, `10-3600`, `0-86400`) are invisible until a bad value throws.
3. **No essential/advanced split.** Connection-level settings (SSL, caller ID, timeout) are interleaved flat with conversation tuning. For the core goal - pick an agent, point at the bridge, control SSL - everything else is tuning that belongs behind an "Advanced" fold with sane defaults.
4. **"Agent" is ambiguous.** Since the integration moved to one conversation entity per agent (CR-0003 subentries), a single top-level "Agent" picker that also drives voice reads as a conflict. It is actually the default / voice agent and the caller-id fallback.

---

## Proposed Changes

### Item 1: Add the two missing labels + help text

**Priority:** P2
**Effort:** S

Add `strings.json` / `translations/en.json` entries:
- `session_idle_window` -> "Session Continuity Window (seconds)" with help: how long related turns reuse the same bridge session before the channel key rotates; `0` = no continuity, `86400` = bridge 24h cap.
- `enable_streaming` -> "Stream replies to voice (experimental)" with help: lower TTS latency by streaming deltas; falls back to non-streaming on any error.

### Item 2: Add help text + ranges to every non-obvious field

**Priority:** P2
**Effort:** S

`data_description` for `context_max_chars` (what it budgets + range), `thinking_timeout` (how long Assist waits + range), `ssl_verify` (turn off only for self-signed/LAN), `debug_logging`.

### Item 3: Rename the agent picker

**Priority:** P3
**Effort:** XS

"Agent" -> "Default / voice agent", with help text noting that additional agents are added as separate conversation entities via "Add agent".

### Item 4: Essential vs Advanced grouping

**Priority:** P2
**Effort:** M

Group the form so essentials (agent, SSL) are first and tuning (max chars, timeout, session window, streaming, caller id, debug) sits in an advanced section. Implement via HA's section/collapsible support in the options schema (preferred) or a second step. Confirm the pattern against current HA docs (Context7) before building.
