# CR-0010: Agent memory record/recall from Home Assistant

> **Status:** Proposed
> **Priority:** P2
> **Type:** feature-request
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** client, services
> **Depends on:** CR-0008
> **GitHub Issue:** —

## Summary

Expose the bridge's per-agent persistent memory (`GET/POST /v1/agents/{id}/memory`) through Home Assistant services, so the operator can have an agent remember and recall home facts ("the back door sticks", "bins go out Tuesday") that persist across conversations.

## Problem

The bridge gives each agent durable memory, but the HA integration has no way to record or recall it. Useful home knowledge is therefore confined to whatever fits in a single conversation's context. Surfacing record/recall makes the agent measurably smarter about the home over time.

---

## Proposed Changes

### Item 1: `agent_bridge.memory_record` service

**Priority:** P2
**Effort:** S

A service taking text (+ optional tags) that POSTs to `/v1/agents/{id}/memory` for the selected agent. Callable from automations and the developer tools.

### Item 2: `agent_bridge.memory_recall` service

**Priority:** P2
**Effort:** S

A service taking a query that GETs `/v1/agents/{id}/memory` and returns matches as a service response (HA `SupportsResponse`). Honour the bridge's honest pagination (`hasMore`, since 4.114).

### Item 3 (optional follow-up): fold recent memory into grounding

**Priority:** P3
**Effort:** M

Optionally inject a small, recent memory slice into the conversation grounding envelope. Flagged as a follow-up, off by default - context-budget and relevance need care before this becomes automatic.

---

## Impact Assessment

### Existing Functionality

Additive. Items 1-2 are new services; item 3 (if taken) touches the grounding envelope built in `conversation.py` and would be opt-in.

None.
