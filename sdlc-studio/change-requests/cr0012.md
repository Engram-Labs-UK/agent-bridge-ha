# CR-0012: Make the fleet-doctor repair issue opt-in (default off)

> **Status:** Implemented
> **Priority:** P2
> **Type:** production-feedback
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** const, config_flow, drift, strings/translations
> **Depends on:** CR-0009 (introduced the feature)
> **GitHub Issue:** —

## Summary

The CR-0009 fleet-doctor repair issue is on by default. On the live install it raised a persistent HA repair for a benign idle fleet ("no fleet activity ~46 min"). 0.10.3 (BG0011) narrowed it to CRITICAL-only, but a fleet-health diagnostic raising HA repairs is an operator concern most users do not want surfaced. Make it **opt-in** (default off).

## Problem

A persistent HA repair notification for fleet health is intrusive for a typical home user. The feature is useful for an operator monitoring the fleet, but should not be on by default.

---

## Proposed Changes

### Item 1: Add a "Fleet health alerts" option (default off) and gate the repair

**Priority:** P2
**Effort:** S

- `const.CONF_DOCTOR_ALERTS = "doctor_alerts"` (default `False`).
- Add the toggle to the options Advanced section.
- `drift.async_check_doctor_verdict`: when the option is off, delete any existing `fleet_doctor` issue and return. When on, keep the CRITICAL-only mapping (BG0011).
- Keep polling `/v1/doctor` so the diagnostics download still carries the verdict; only the repair issue is gated.

---

## Impact Assessment

### Existing Functionality

On upgrade the standing fleet-doctor repair clears (option defaults off). Diagnostics still include the doctor verdict.
