# CR-0013: Options-flow refinements — remove Caller ID + Voice debug; session-continuity preset dropdown

> **Status:** Implemented
> **Priority:** P3
> **Type:** production-feedback
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** const, config_flow, conversation, helpers, strings/translations
> **Depends on:** CR-0007 (the options structure)
> **GitHub Issue:** —

## Summary

An options-screen review found three settings worth changing: **Caller ID** is niche and a free-text identity footgun; **Voice debug logging** duplicates HA's built-in per-integration debug logging; and **Session continuity window** is a raw seconds box no one will type into. Remove the first two and turn the third into a friendly preset dropdown. **Stream replies to voice** stays (kept as experimental).

## Problem

- Caller ID: rarely needed (blank already falls back to the selected agent), and exposing a free-text caller identity invites misconfiguration.
- Voice debug logging: redundant with HA's native ⋮ → "Enable debug logging" per config entry.
- Session continuity: a `0-86400` seconds field is unfriendly; presets are clearer.

---

## Proposed Changes

### Item 1: Remove the Caller ID option

**Priority:** P3
**Effort:** S

Drop `CONF_CALLER_ID` from the options schema + `const.py`; simplify `resolve_caller_id` to `default_agent → DEFAULT_CALLER_ID`. A previously-stored `caller_id` is ignored (harmless; the selected agent is always a registered caller, BG0004).

### Item 2: Remove the Voice debug logging toggle

**Priority:** P3
**Effort:** S

Drop `CONF_DEBUG_LOGGING` from the schema, its setup seed, and `const.py`. Emit the per-turn log at `debug` level so HA's built-in per-entry debug logging captures it (the standard pattern).

### Item 3: Session-continuity preset dropdown

**Priority:** P3
**Effort:** M

Replace the int field with a `SelectSelector` (dropdown): Off / 5 minutes / 30 minutes / 2 hours / 8 hours / 24 hours (`0/300/1800/7200/28800/86400`). Coerce the selected string to `int` on submit so `conversation.py` is unchanged. New default 5 minutes (`DEFAULT_SESSION_IDLE_WINDOW=300`). Pre-select defensively for a stored non-preset value.

### Item 4: Stream replies to voice — keep

No change. Verified during planning that it only helps with a streaming-capable TTS engine (most are 1-shot → HA falls back); kept as experimental, off by default.

---

## Impact Assessment

### Existing Functionality

No behavioural change beyond the removed options (orphaned stored values ignored) and the new session default for fresh installs. `conversation.py` reads the session window as an int regardless of stored value.

### Affected Modules

| Module | Impact | Change Type |
| --- | --- | --- |
| `config_flow.py` | schema: remove 2 fields, session dropdown, submit coercion | Modified |
| `const.py` | remove `CONF_CALLER_ID`/`CONF_DEBUG_LOGGING`; `DEFAULT_SESSION_IDLE_WINDOW=300` | Modified |
| `helpers.py` | `resolve_caller_id` simplified | Modified |
| `conversation.py` | debug-level per-turn log | Modified |
| `strings.json`/`translations/en.json` | remove 2 labels | Modified |

### Breaking Changes

The Caller ID and Voice-debug options disappear from the UI. No functional break (fallbacks cover both).
