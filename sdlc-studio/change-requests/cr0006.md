# CR-0006: Cull dead and no-op options-flow controls

> **Status:** Proposed
> **Priority:** P2
> **Type:** design-change
> **Requester:** Darren Benson
> **Date:** 2026-06-09
> **Affects:** config_flow, tool_executor, event, conversation, const, strings/translations
> **Depends on:** —
> **GitHub Issue:** —

## Summary

Remove options-flow controls and code paths that no longer do anything after the move to agent-side actuation (the agent actuates HA via its own `/api/mcp` mount; this integration no longer runs an HA tool loop - US0027/US0031). Three things no longer earn their place: the "Allow tool execution" checkbox, the orphaned HA-side tool executor, and the "Context Overflow Strategy" radio.

## Problem

A review of the options flow against the "thin adapter, no duplication of bridge logic" principle found controls that mislead or do nothing:

1. **"Allow tool execution" gates nothing.** `CONF_ENABLE_TOOL_CALLS` is read only in `config_flow.py` (to render and default the checkbox). The conversation path never reads it, never sends a `tools=` schema to the bridge, and never calls the executor. The agent reaches back into HA through HA's own MCP Server integration. A user who unticks this still has a fully actuating agent - the control is both a no-op and actively misleading. This integration cannot gate the agent's MCP actuation from here even if it wanted to (that lives in HA's MCP Server integration / entity exposure).

2. **`tool_executor.py` is dead code.** `execute_tool_call` is defined but never called anywhere. It is a remnant of the pre-realignment architecture where HA executed the agent's `tool_calls`.

3. **`EVENT_TOOL_INVOKED` / `ToolInvokedEvent` never fire.** The "Tool Invoked" event entity (`event.py`) listens for `EVENT_TOOL_INVOKED`, which only the dead executor emits. The live audit surface is `EVENT_ACTUATION_AUDIT`, which carries per-*turn* data (agent, area, risky domains, severity) but no per-tool detail, because the actual tool calls happen on the agent's MCP mount and are invisible to this integration. So the entity cannot be faithfully rewired and never lights up.

4. **"Context Overflow Strategy" (truncate/clear) is an over-exposed niche toggle.** `clear` drops *all* HA entity state from the prompt when over budget - rarely what anyone wants. `truncate` (keep whole lines until the budget runs out) is the sane always-choice.

---

## Proposed Changes

### Item 1: Remove the "Allow tool execution" control

**Priority:** P2
**Effort:** S

Remove `CONF_ENABLE_TOOL_CALLS` from the options schema (`config_flow.py`), its seed in `async_step_agents`, the `strings.json` / `translations/en.json` label, and the constant. No runtime path reads it.

### Item 2: Delete the orphaned HA-side tool executor

**Priority:** P2
**Effort:** S

Delete `tool_executor.py` and its test `tests/test_tool_executor.py`. Remove `DEFAULT_TOOL_TIMEOUT` (used only by the executor).

### Item 3: Remove the dead Tool Invoked event path

**Priority:** P2
**Effort:** S

Remove `ToolInvokedEvent` from `event.py` and the `EVENT_TOOL_INVOKED` constant. (Per-tool actuation visibility, if wanted, is a *new feature* - the agent's MCP mount is the only place that sees individual calls - and is tracked separately, not restored here.)

### Item 4: Remove the "Context Overflow Strategy" radio

**Priority:** P3
**Effort:** S

Stop reading `CONF_CONTEXT_STRATEGY` in `conversation.py` (let `build_entity_context` default to `truncate`). Remove the field from the `config_flow.py` schema, its seed, and the `strings.json` / `translations/en.json` label. Keep `build_entity_context`'s `strategy` parameter (defaulted `truncate`) so the function and `test_exposure.py` are unaffected.

## Impact Assessment

### Existing Functionality

No behavioural change. Every removed control is already a no-op or an always-defaulted niche toggle. Actuation, entity-context budgeting (`truncate`), and the audit surface are unchanged.

### Affected Modules

| Module | Impact | Change Type |
| --- | --- | --- |
| `config_flow.py` | Two options fields removed | Modified |
| `tool_executor.py` | Deleted | Removed |
| `event.py` | `ToolInvokedEvent` removed | Modified |
| `conversation.py` | Stop reading `CONF_CONTEXT_STRATEGY` | Modified |
| `const.py` | Remove `CONF_ENABLE_TOOL_CALLS`, `CONF_CONTEXT_STRATEGY`, `EVENT_TOOL_INVOKED`, `DEFAULT_TOOL_TIMEOUT`, `DEFAULT_CONTEXT_STRATEGY` | Modified |
| `strings.json` / `translations/en.json` | Remove two labels | Modified |
| `tests/` | Delete `test_tool_executor.py`; update `test_config_flow.py`, `conftest.py` | Modified |

### Breaking Changes

The "Tool Invoked" event entity is removed. It never fired, so no working automation depends on it, but it is a user-visible entity id disappearing - note in the changelog.
