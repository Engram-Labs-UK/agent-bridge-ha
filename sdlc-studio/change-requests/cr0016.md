# CR-0016: Service-layer and setup polish (default-agent parity, proper service errors, dead sensor cull, self-signed onboarding)

> **Status:** Proposed
> **Priority:** P3
> **Type:** design-change
> **Requester:** Code + security review (RV-requested, 2026-07-04)
> **Date:** 2026-07-04

> **Depends on:** —

## Summary

Four small consistency/correctness items from the 0.11.0 full review, none release-blocking, grouped because they share the "polish the operator-facing seams" theme.

## Problem

Documented behaviour diverges from code in the service layer, service errors surface as raw `ValueError`s, one platform class is dead code, and a self-signed-TLS bridge cannot be onboarded at all.

---

## Proposed Changes

### Item 1: `send_message` / `ask_with_image` default-agent fallback (docs parity)

**Priority:** P3 · **Effort:** XS

`services.yaml` says `agent_id` "Defaults to the configured default agent", but both handlers pass `agent=None` (bridge routing decides). The memory services already fall back via `_default_agent(hass)`. Either apply the same fallback in `send_message`/`ask_with_image`, or fix the YAML wording — pick the fallback for consistency (one behaviour across all four agent-taking services).

### Item 2: Raise `ServiceValidationError` instead of `ValueError`

**Priority:** P3 · **Effort:** S

`_get_entry_data` and `_validate_agent_id` raise bare `ValueError` ("Unknown agent: x"), which HA reports as an internal error rather than a user-input problem. Use `homeassistant.exceptions.ServiceValidationError` (translated) so automations/UI get a proper validation failure.

### Item 3: Remove the dead `PerAgentHealthSensor`

**Priority:** P4 · **Effort:** XS

`binary_sensor.PerAgentHealthSensor` (binary_sensor.py:67-123) is never instantiated — `async_setup_entry` only adds `BridgeConnectedSensor`. Per the CR-0006 cull doctrine: delete it (per-agent health is already on the coordinator/diagnostics), or wire it up deliberately with a story. Recommend delete.

### Item 4: Allow disabling SSL verification during initial setup

**Priority:** P3 · **Effort:** S

`CONF_SSL_VERIFY` exists only in options, but the first-run flow hardcodes `ssl_verify=True` (config_flow.py:123) — a bridge behind self-signed HTTPS fails `check_alive` and the entry can never be created, so the option is unreachable. Add an advanced checkbox to the user step (default on), stored into the created entry's options.

Item 1 changes routing for `send_message`/`ask_with_image` calls that omit `agent_id`: they will now target the configured default agent instead of bridge auto-routing. That matches the documented behaviour, but note it in the changelog.
